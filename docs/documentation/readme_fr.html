Virevo : paiement par virement instantané

Module PrestaShop virevopay, version 0.6.2. PrestaShop 1.7.6 à 9.x.

1. Ce que fait le module

Le module ajoute au tunnel de commande un moyen de paiement « Payer par virement instantané ». Le client choisit sa banque, valide le virement dans son application bancaire, et la commande passe d'elle-même en « Paiement accepté ». L'argent va directement du compte du client à votre IBAN : Virevo ne détient jamais vos fonds.

2. Prérequis

  • PrestaShop 1.7.6 à 9.x, PHP avec l'extension cURL.
  • Une boutique qui vend en euros.
  • Un compte Virevo (inscription sur virevo.fr). Virevo prélève des frais sur chaque paiement reçu, sans abonnement. Tarifs : virevo.fr/#tarif
  • Une boutique joignable depuis internet, pour que Virevo puisse appeler son URL de webhook.

3. Installation

  1. Dans l'administration, ouvrez Modules › Gestionnaire de modules et cliquez sur Importer un module.
  2. Choisissez le fichier virevopay-0.6.2.zip. PrestaShop installe le module.
  3. Cliquez sur Configurer sur le module.

4. Configuration

ChampÀ saisir
ModeTest (bac à sable) pour essayer le module, Live pour recevoir de vrais paiements.
Clé API testVotre clé commençant par vrv_test_, dans Virevo › Développeurs.
Clé API liveVotre clé commençant par vrv_live_, dans Virevo › Développeurs. Disponible une fois votre compte Virevo vérifié.
Secret de webhookLe secret commençant par whsec_, dans Virevo › Développeurs.

Sous le champ du secret, le module affiche l'URL de webhook de votre boutique. Copiez-la et enregistrez-la dans Virevo › Développeurs. Sans elle, les commandes restent « En attente de virement » alors que le client a payé.

Le moyen de paiement reste masqué aux clients tant qu'aucune clé d'API valide n'est saisie pour le mode choisi. La page de réglages vous avertit aussi quand le secret de webhook manque.

5. Tester avant de passer en réel

  1. Laissez le mode sur Test. Les paiements sont fictifs : aucun argent ne bouge.
  2. Dans Virevo › Développeurs, le bouton Envoyer un test envoie un événement signé à votre URL de webhook. Il vérifie que Virevo joint bien votre boutique.
  3. Passez une commande sur votre boutique en choisissant « Payer par virement instantané ». La commande est créée en « En attente de virement » et vous êtes redirigé vers la page de paiement Virevo.
  4. Pour simuler un paiement reçu, suivez la section « Mode test » du guide développeurs sur virevo.fr/developpeurs. La commande passe alors en « Paiement accepté ».
  5. Quand tout fonctionne, saisissez votre clé live et passez le mode sur Live.

6. États de commande

Événement chez VirevoÉtat de la commande PrestaShop
Le client clique sur « Commander »En attente de virement
Paiement reçuPaiement accepté
Paiement refusé par la banqueErreur de paiement
Paiement annulé ou expiréAnnulé (stock restitué)
Remboursement totalRemboursé

Chaque webhook est vérifié par une signature HMAC-SHA256 et un horodatage, ce qui bloque les messages falsifiés ou rejoués.

7. Remboursements

Pour rembourser un client, créez un avoir sur la commande dans PrestaShop (remboursement partiel ou total). Le module transmet le remboursement à Virevo automatiquement.

Un remboursement fait directement dans votre compte Virevo est signalé sur la commande par un message privé, et la commande passe en « Remboursé » s'il couvre le total. Aucun avoir n'est créé dans ce cas : créez-le vous-même si vous en avez besoin, il ne déclenchera pas de second remboursement.

8. Si Virevo est injoignable

Si le paiement ne peut pas être créé (panne réseau, maintenance), la commande est annulée et son stock restitué. Le client retrouve son panier avec un message et peut réessayer ou choisir un autre moyen de paiement.

9. Données transmises à Virevo

Seuls le montant, la devise, le numéro de commande et les adresses de retour de la boutique sont envoyés à Virevo. Aucune donnée personnelle du client ne transite par le module.

10. Limites

  • Euros uniquement. Montant minimal : 1 € TTC. En dessous, le moyen de paiement n'est pas proposé.
  • Les écrans d'administration du module sont en français.
  • Non testé avec les modules de commande en une page d'éditeurs tiers.

11. Désinstallation

Dans Modules › Gestionnaire de modules, désinstallez le module. Ses réglages sont supprimés. Les commandes passées sont conservées avec leur état.

12. Support

Posez vos questions par la messagerie de PrestaShop Addons, depuis la page du module.
